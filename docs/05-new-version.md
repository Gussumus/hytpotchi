# Как выпустить новую версию

Делается каждый раз, когда вы что-то поменяли в лаунчере (или добавили новую переменную в GitHub)
и хотите, чтобы это получили все игроки.

**Время:** 2 минуты вашего времени + 15–25 минут сборки на GitHub.

[← К оглавлению](SETUP.md)

---

## Номер версии

Версия выглядит как `v0.2.0` — три числа через точку:

| Что изменилось | Как менять номер | Пример |
|---|---|---|
| Исправили ошибку, мелочь | последнее число +1 | `v0.2.0` → `v0.2.1` |
| Добавили новую возможность | среднее +1, последнее = 0 | `v0.2.1` → `v0.3.0` |
| Огромное обновление | первое +1, остальные = 0 | `v0.9.3` → `v1.0.0` |

> ⚠️ **Новый номер всегда должен быть больше предыдущего.** Иначе лаунчеры у игроков не увидят обновление.
> Один и тот же номер нельзя использовать дважды.

Какие версии уже были — видно на GitHub во вкладке **Releases** или командой:

```bash
git tag
```

---

## Выпуск по шагам

Откройте терминал в папке проекта ([как](SETUP.md#как-открыть-терминал-в-папке-проекта)).

**1. Если вы меняли файлы** — сохраните и отправьте изменения
(если просили меня, Claude, сделать изменения и коммит — этот пункт уже сделан, переходите к шагу 2):

```bash
git add -A
```

```bash
git commit -m "Коротко, что изменилось"
```

```bash
git push
```

**2. Поставьте метку версии и отправьте её** (замените `v0.2.1` на свою новую версию):

```bash
git tag v0.2.1
```

```bash
git push origin v0.2.1
```

**3. Дождитесь сборки:** GitHub → вкладка **Actions** → задача **Release**.
Жёлтый кружок — собирается, зелёная галочка ✅ — готово, красный крестик ❌ — см. [06-problems.md](06-problems.md).

**4. Всё.** Новая версия появится в **Releases**, а у игроков при следующем запуске лаунчера будет
уведомление **«Доступна новая версия → Обновить»**. Нажатие — и лаунчер обновится и перезапустится сам.

---

## Если добавили только переменную в GitHub

Например, вставили `HYTPOTCHI_DISCORD_ID`, а код не меняли — шаг 1 пропускаете,
сразу делаете шаг 2 с новым номером версии. Переменные «вшиваются» в лаунчер при сборке.

---

## Удалить неудачную версию

Если версия собралась с ошибкой и вы хотите её убрать:

1. GitHub → **Releases** → нужный релиз → значок корзины 🗑 (**Delete**).
2. Удалите метку:

```bash
git push --delete origin v0.2.1
```

```bash
git tag -d v0.2.1
```

3. Исправьте ошибку и выпустите **следующий** номер (например `v0.2.2`) — не переиспользуйте старый.
